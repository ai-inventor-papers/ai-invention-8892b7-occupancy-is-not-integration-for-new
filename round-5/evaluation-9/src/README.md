# Paper figures drawn straight from result files

This builds the figure set for the Applied Network Science paper: F1–F7, F6b and an inferential-caveats table. Every figure is drawn deterministically from result files that earlier artifacts wrote to the run volume. Nothing is re-estimated.

Each plotted number, including CI endpoints and annotation text, comes from one source registry (`sources.yaml`). The registry names the producing artifact id, a run-root-relative path and a selector. Every source file is sha256-hashed when first read. Independent checks then re-read each value from its source and assert equality. A drift report compares the numbers quoted in the hypothesis/record with those sources.

`make_all.py` regenerates everything, and `eval.py` scores it (`eval_out.json`, schema `exp_eval_sol_out`).

## Known discrepancies for the paper step (`results/drift_report.csv`)

- **Screen entry count.** "1,740 screen entries" matches `rooting.json` (and `d2_models.json` sample 1,740 after dropping 6 rows with missing controls). The raw event count in `d2_summary.json` `events.MAIN_kw5_by_fold.screen` is 1,746. The paper should name the denominator.
- **Robustness count.** "26 of 27" (the iteration-4 claim) is wrong. The recount gives 20 of 26 rows, or 18 of 22 excluding the base row and strata (`robustness_recount.json`).
- **"1,344 of 1,544 single-paper".** No source file contains this count (NOT_FOUND). The nearest stored quantity is `g_screen_summary.json` `G1_descriptive.share_single_paper_entry_year` = 0.832 over 1,969 window events. Do not cite 1,344 until it is sourced.
- **"About 84k edges".** F1 prints the 2023 snapshot (27,075 nodes, 98,514 kept edges). 84k matches the median kept-edge count over 2000–2024 (83,875), not 2023. The record should say which.
- **F2 placebo rows.** Main-fold placebo-host rows show the median and 2.5–97.5% quantiles of 100 size-matched draws, not a CRV1 CI. The MeSH placebo row is a CRV1 CI. Both are labelled.
- **F1 side panel.** Definitions for E_up and persistent-neighbour closure are not stored as strings in any source spec file, so they print "n/a - source missing". Definitions for A_cont, CT, Y_strict, EST_bin and the folds are quoted verbatim from `d2_prereg.json` / `d2_summary.json`.
- **F7.** The K1–K3 files found at build time (`gen_art_evaluation_6/results/k1_rows.csv`, `k3_rows.csv`) use different column names (`estimate`, `ci_lo`, `ci_hi`, `unit`) from `figures/F7/k_rows.schema.json`, so F7 ships as a template (`figures/F7/STATUS.txt`).
- **F4.** The screen pooled-panel estimate for effective size, and the screen pooled-panel SE for within-module z, are empty cells in `r1_pooled_panel_screen_vs_heldout.csv`. They are drawn as "not estimated in source" and as a point without CI.

## Restoring removed files

`.aii/manifest.yaml` marks these paths for deletion before publishing. Each is regenerable with the command shown, run from this folder:

| Removed path | Command that brings it back |
|---|---|
| `.venv/` | `uv venv .venv --python=3.12 && uv pip install --python .venv/bin/python -r requirements.txt` |
| `.pytest_cache/` | `.venv/bin/python -m pytest -q` |
| `src/__pycache__/`, `src/plots/__pycache__/` | `.venv/bin/python make_all.py` |
| `checks/__pycache__/` | `.venv/bin/python eval.py` |

`figures/`, `tables/` and `results/` are small text/image deliverables and are always published. They can also be rebuilt with `make_all.py`, `checks/selftest_mutation.py` and `eval.py` (see `reproducibility.md`), as long as the source artifacts are reachable under `AII_RUN_ROOT`.

## How to run

```bash
uv venv .venv --python=3.12 && uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python make_all.py                   # figures/ and tables/
.venv/bin/python checks/selftest_mutation.py   # mutation + lint self-test
.venv/bin/python eval.py                       # checks + eval_out.json
.venv/bin/python -m pytest -q                  # 12 tests
```
